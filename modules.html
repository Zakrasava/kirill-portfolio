    Каждый модуль: что это, для кого, что было, что стало, результат. Блок «Технически» — для специалистов. Цифры со знаком ≈ — оценка по времени операций до и после.

    Входящие письма

    Карточка письма заполняется из скана; регистратор только проверяет и подтверждает.

    Для кого: Регистраторы входящей корреспонденции.

    Было

    1. Скан на три страницы читают целиком.
    2. Заводят карточку из двух десятков полей вручную.
    3. Переносят строку в реестр в Excel, потом — в 1С.
    4. Часть писем терялась между почтой и реестром.
    →

    Стало

    1. Письмо попадает в модуль само.
    2. Система распознаёт текст и заполняет карточку.
    3. Регистратор видит скан и карточку рядом — подтверждает одним нажатием.
    4. Реестр заполняется автоматически.
    −113 человеко‑дней в годрегистрация ≈ минута вместо 10–15; качество считается по реальным правкам полей
    Технически — для специалистов
    • Распознавание сканов (OCR), затем локальная языковая модель Qwen через Ollama заполняет карточку из 23 полей.
    • Ветка обработки выбирается автоматически или вручную; очередь на диске переживает перезапуск сервера.
    • Метрика качества — доля карточек без единой правки регистратора; недельная динамика для руководства.

    Формирование спецификаций

    Спецификация к договору собирается из документов поставщика, а не набирается вручную.

    Для кого: Специалисты по комплектации и закупкам.

    Было

    1. Спецификацию собирали вручную из писем и прайсов поставщика.
    2. Одни и те же позиции перепечатывали из файла в файл.
    →

    Стало

    1. Файлы поставщика загружаются в модуль.
    2. Спецификация собирается автоматически в нужной форме.
    3. Человек проверяет и выгружает готовый документ.
    ≈ минуты вместо часовна подготовку спецификации к договору
    Технически — для специалистов
    • Разбор таблиц и PDF поставщиков; шаблоны генеральной и табличной спецификаций; выгрузка в Excel и PDF.

    Сверка спецификаций

    Каждая позиция спецификации сверяется с учётной системой; расхождения показаны списком.

    Для кого: Специалисты по комплектации и закупкам.

    Было

    1. Открывали 1С и сверяли каждую позицию глазами: наименование, количество, цена.
    2. Расхождения находили не все и не сразу.
    →

    Стало

    1. Спецификация сверяется с данными учётной системы автоматически.
    2. Расхождения показаны списком — их не нужно искать по строкам.
    ≈ минуты вместо половины дняна сверку спецификации из 200 позиций
    Технически — для специалистов
    • Сопоставление позиций с номенклатурой учётной системы (полнотекстовый и нечёткий поиск).
    • Данные 1С — только на чтение, через согласованную интеграцию; список расхождений хранится в истории.

    Согласование спецификаций

    Согласование идёт внутри платформы: версии, замечания, кто и когда согласовал.

    Для кого: Закупщики, руководители управлений, согласующие службы.

    Было

    1. Спецификацию гоняли по почте: «см. вложение, версия 7 финальная 2».
    2. Замечания терялись в переписке.
    3. Кто согласовал и когда — восстанавливали по письмам.
    →

    Стало

    1. Одна карточка спецификации с версиями.
    2. Замечания привязаны к версии и позиции.
    3. История согласования видна сразу.
    одна версия вместо десяти писемистория согласования — в системе, а не в почте
    Технически — для специалистов
    • Маршрут согласования с ролями; уведомления участникам; журнал изменений по каждой версии.

    История цен закупок

    Единая база всех закупленных позиций с поиском и графиком цены по времени.

    Для кого: Закупщики и руководители — при подготовке закупки и переговорах с поставщиком.

    Было

    1. «Почём брали трубу 57×3,5 в прошлом году?» — поиск по папкам и памяти коллег.
    2. Час‑два, и не всегда с результатом.
    →

    Стало

    1. Поиск по названию позиции.
    2. График цены по времени, поставщик, дата, количество, договор.
    ≈ секунды вместо часоваргумент для переговоров с поставщиком всегда под рукой
    Технически — для специалистов
    • Полнотекстовый индекс по номенклатуре; история цен собирается из спецификаций и реестров платформы.
    • График строится на стороне браузера; выгрузка выборки в Excel.

    Акты М‑7

    Акты приёмки материалов разбираются автоматически и попадают в реестр.

    Для кого: Специалисты комплектации и склада.

    Было

    1. Акты приходили таблицами разного формата.
    2. Их сводили в реестр вручную, позиция за позицией.
    →

    Стало

    1. Файл загружается в модуль.
    2. Позиции разбираются автоматически; реестр ведётся сам.
    реестр без ручного вводаразные форматы таблиц — один реестр
    Технически — для специалистов
    • Разбор Excel‑файлов разных форм; нормализация позиций; реестр с фильтрами и выгрузкой.

    Протоколы совещаний

    Из аудиозаписи совещания — черновик протокола с решениями, сроками и ответственными.

    Для кого: Секретари совещаний, руководители.

    Было

    1. Протокол писали полдня по своим заметкам.
    2. Решения и ответственные терялись.
    →

    Стало

    1. Загружается запись совещания.
    2. Система делает расшифровку и черновик протокола.
    3. Человек правит и отправляет.
    ≈ 15 минут после совещаниявместо половины дня
    Технически — для специалистов
    • Распознавание речи локальной моделью Whisper; языковая модель выделяет решения, сроки и ответственных.
    • Все записи остаются на сервере компании.

    Презентации для руководства

    Отчётная презентация собирается по шаблону из данных платформы.

    Для кого: Руководители управлений и их помощники.

    Было

    1. Презентацию собирали руками из одних и тех же таблиц — каждый раз заново.
    →

    Стало

    1. Выбирается шаблон и период.
    2. Слайды заполняются данными платформы.
    ≈ минуты вместо вечераданные всегда актуальные
    Технически — для специалистов
    • Генерация файлов презентаций по шаблонам; данные — из модулей платформы.

    Задачи

    Поручения с исполнителем, сроком и проверяющим; просроченное видно на одном экране.

    Для кого: Руководители и сотрудники управлений.

    Было

    1. Поручения в мессенджерах и на словах.
    2. Кто что должен и к какому сроку — неясно.
    →

    Стало

    1. Задача с исполнителем, сроком и проверяющим.
    2. Руководитель видит просроченное на одном экране.
    ничего не теряетсякаждое поручение — с ответственным и сроком
    Технически — для специалистов
    • Статусы, роли проверяющего, уведомления; журнал изменений по задаче.

    Отсутствия и командировки

    Заявка, согласование и отчёт по подразделению — в системе, с календарём отсутствий.

    Для кого: Все сотрудники и их руководители.

    Было

    1. Журнал командировок — тетрадь.
    2. Согласование — обход кабинетов с бумагой.
    3. Отчёт по подразделению — вручную в конце месяца.
    →

    Стало

    1. Заявка подаётся в системе или через бота.
    2. Согласование — в один клик у руководителя.
    3. Календарь и отчёт по подразделению — автоматически.
    ≈ минуты вместо дняна согласование одной заявки
    Технически — для специалистов
    • Заявки и согласования через веб и Telegram‑бота; календарь подразделения; выгрузка отчёта.

    Чат сотрудников

    Внутренняя переписка по задачам и документам внутри контура компании.

    Для кого: Все сотрудники платформы.

    Было

    1. Рабочая переписка велась в личных мессенджерах, вне контура компании.
    →

    Стало

    1. Переписка по задачам и документам — внутри платформы.
    2. История доступна участникам и хранится на сервере компании.
    переписка внутри контурадоступ по правам, история сохраняется
    Технически — для специалистов
    • Каналы и личные сообщения; уведомления; хранение на сервере компании.

    Метрики для руководства

    Нагрузка по людям, сроки и качество обработки — на одном экране, всегда актуально.

    Для кого: Руководители управлений.

    Было

    1. «Пришлите отчёт» — и день на сбор цифр из разных источников.
    →

    Стало

    1. Экран руководителя: нагрузка по людям, сроки, доля документов без правок.
    2. Данные обновляются сами.
    отчёт без запросацифры считаются по данным модулей
    Технически — для специалистов
    • Агрегация по данным модулей; недельная динамика; права по управлениям.

    ИИ‑помощник

    Вопрос обычным языком — ответ по данным платформы, только в рамках прав пользователя.

    Для кого: Все сотрудники платформы.

    Было

    1. Чтобы узнать, какие письма от поставщика пришли за месяц, искали по реестру вручную.
    →

    Стало

    1. Вопрос в чате: «какие письма от поставщика X за месяц?»
    2. Ответ по данным платформы — только по тем, к которым у человека есть доступ.
    ответ по данным компаниибез выхода данных наружу
    Технически — для специалистов
    • Локальная языковая модель; поиск по документам через векторный индекс; фильтр по правам пользователя применяется до ответа.

    Права, журнал, безопасность

    Права выдаются по управлениям, каждое действие записано в журнал, данные не покидают компанию.

    Для кого: Администраторы платформы и служба информационной безопасности.

    Было

    1. Доступы раздавались по договорённости; кто что делал — не восстановить.
    →

    Стало

    1. Права на модули — по управлениям, каждый видит только своё.
    2. Журнал: кто, что, когда, над каким объектом.
    3. Языковая модель работает на сервере компании; связь с 1С — только чтение.
    данные не покидают компаниюпо требованиям компании к персональным данным (152‑ФЗ)
    Технически — для специалистов
    • Роли и права по управлениям; журнал аудита каждого действия; шифрование персональных данных.
    • Ежедневные и внешние резервные копии; релизные ворота и автоматический деплой; 2 222 автотеста.
    • Интеграция с 1С в режиме чтения согласована со службой ИБ.
